# 任务状态同步规则

> 优先级：高
> 创建：2026-08-15 ｜ 公开版：v5.2.0
> 来源：一次合并后用户界面显示“3 个任务未完成”，实际工作已经做完但从未标记；新会话又凭旧快照汇报“没有任务了”。

---

## 核心规则

**执行完成不等于任务完成。** 一项工作必须同时满足“已执行 + 已标记 + 已验证”才算完成，三者缺一即未完成。

## 规则 1：做完立即标记

```
Step 1: 执行完成
Step 2: 立即在正式任务系统里标记完成
Step 3: 标记时附带产出文件路径
Step 4: 回读任务状态，确认确实变为完成
```

## 规则 2：区分两类任务清单

| 类型 | 用途 | 是否跨会话 |
|---|---|---|
| 正式任务系统（项目看板、Issue、任务文件） | 用户要交付、跨会话的工作 | 是 |
| 会话内待办清单 | 本次会话的临时跟踪 | 通常不恢复 |

跨会话的工作必须记录在正式任务系统，不得只依赖会话内清单。

## 规则 3：新会话核实真实状态

新会话开始或用户提到“还有任务没做完”时：拉取正式任务状态 → 与界面快照对比 → 不一致时逐项查产出文件 → 按真实状态告知用户。禁止凭空清单断言“没有任务了”。

## 规则 4：收尾自检

- 本轮声称完成的每一项，在正式任务系统里都是完成状态
- 每个完成项都带产出路径
- “待用户决策”与“已完成”明确区分

## 规则 5：禁止假标

为了界面整洁把没做完的任务标成完成，是比漏标更严重的事故。
