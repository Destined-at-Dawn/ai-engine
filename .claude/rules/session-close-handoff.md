# 会话收尾与交接索引规则

> 优先级：高
> 创建：2026-08-04 ｜ 更新：2026-11-11 ｜ 公开版：v5.2.0
> 来源：①上下文用尽后新会话从零开始，前一轮的决策和死路全部丢失。②交接提示词写了很多份却没有状态索引，一项安全优先级最高的待办在交接文件里躺了 13 天无人执行。

---

## 触发条件

任一情况出现即执行：对话结束或用户说“收尾”；上下文即将压缩；用户要求生成新会话提示词；一个任务完成，需要沉淀。

## 五步收尾

### Step 1：定位工作日志目录

在当前工作区根目录探测 `work-logs/`（兼容 `work-log`、`work_logs`）。存在就复用并先读现有文件；不存在再新建。以当前工作区为基准，不硬编码到别的工作区。

### Step 2：写上下文摘要

`work-logs/conversation-context-{YYYY-MM-DD}-{主题}.md`：用户请求、技术细节、决策、错误与修复、约束原文、待办、下一步。

### Step 3：更新三份标准文件

| 文件 | 内容 | 动作 |
|---|---|---|
| `current-state.md` | 已核验的事实、主线、待办 | 更新 |
| `decision-log.md` | 日期 / 决策 / 依据 / 影响 | 追加 |
| `negative-results.md` | 方案 / 现象 / 原因 / 退出判据 | 追加 |

### Step 4：更新记忆

每日记忆写任务进展与教训；长期记忆只写持久知识与偏好，标注置信度与失效条件。

### Step 5：生成重启提示词并登记索引

1. 写 `work-logs/prompt-next-session-{YYYY-MM-DD}-{主题}.md`：角色、目标、真源读取顺序、已验证配置、防回归门禁、已知证据、待办、响应约定。
2. 在 `work-logs/HANDOFF-INDEX.md` 登记一行：

```
| 日期 | 交接文件 | 优先级 | 状态（OPEN / DONE / DROPPED） | 终局证据 |
```

## 交接索引规则

- 新会话开工先读 `HANDOFF-INDEX.md`，按优先级处理 `OPEN` 项，不靠记忆找交接文件。
- 安全类 P0 待办单独成一份交接文件，不与普通待办混写。
- 状态改为 `DONE` 必须附终局证据。例如“已从远端历史清除凭据”的证据是远端引用列表与包含关系查询的结果，不是本地操作成功的输出。
- 涉及泄露的凭据：先轮换，再清历史。
