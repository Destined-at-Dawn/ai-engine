# 交付物分层验收规则

> 优先级：高
> 创建：2026-11-01 ｜ 公开版：v5.2.0
> 来源：多次“生成成功”被当成“交付通过”——编译通过的 PDF 版式错位；兼容办公套件能打开的文档在目标软件里弹修复提示；读源码确认已修复的 bug 在线上仍然存在，因为线上跑的是旧构建；文件存在但链接打不开。

---

## 核心规则

**生成成功、文件存在、本地修好，都只是某一层的通过。每一层单独验收，单独记录实测值，不能互相替代。**

## 文档类交付（Word / PDF / 幻灯片）

| 层 | 名称 | 通过判据 |
|---|---|---|
| L1 | 可重建 | 有生成脚本，改文案后能重跑出同样结构 |
| L2 | 结构自洽 | 结构检查脚本全部通过（标题层级、图表编号、引用、页眉页脚） |
| L3 | 目标软件实测 | 在用户实际使用的软件里打开：无修复提示，页数、图片数、页码有实测值 |
| L4 | 视觉与外链 | 导出 PDF 逐页看；每个链接用请求实测返回码 |

- 替代软件打开正常，不算目标软件通过。
- 全文可读，不算逐页视觉通过。修复一处后从第 1 页重新看。
- 从有损转换件（例如格式转换后的副本）上做的核验，不能用来证伪原件的属性。

## 软件与服务类交付

| 层 | 判据 |
|---|---|
| 源码 | 修改已提交，测试通过 |
| 构建 | 产物哈希与源码版本对应 |
| 部署 | 运行环境里的版本标记与本次构建一致 |
| 真实使用 | 在用户实际入口（域名、安装包、设备）完成一次真实操作 |

- “读源码发现已经修过了”不是验证，要确认线上跑的是哪个构建。
- 多入口服务（多个域名、多个客户端）按入口逐个枚举验收，改一个入口不代表全部生效。
- 配置写进去不等于生效：回读运行时实际值，并用一次真实请求证明它起作用。

## 记录格式

```
层级：L3
环境：<软件或平台及版本>
实测值：<页数 / 返回码 / 版本标记>
证据：<截图、日志或回读输出的路径>
未覆盖：<没有验证的层>
```
