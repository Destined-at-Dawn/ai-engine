# Shell 内嵌文本完整性规则

> 优先级：高（与 chinese-path-safety 配套：那条管编码，这条管 shell 解析吞字符）
> 创建：2026-08-19 ｜ 更新：2026-08-29 ｜ 公开版：v5.2.0
> 来源：同类问题三次复现后升级为规则。命令行里内嵌的文本被 shell 先解析了一遍：反引号包住的文件名被当成命令替换执行，落盘内容变成空白；Windows 路径里的 `\a`、`\t` 被当成控制字符吃掉。写入返回成功，内容已经损坏，不报错。

---

## 核心规则

**要落盘的文本（记忆、日志、规则、决策记录、路径、公式）不经过 shell 字符串内嵌。** 用文件编辑工具，或写成独立的脚本文件再执行。

## 规则 1：禁止在双引号字符串里用反引号

在 Bash 双引号字符串里（包括 `python -c "..."` 内部的字符串字面量），反引号会触发命令替换：内容被吞，只留下一条 `command not found`。

## 规则 2：路径与多行文本写进脚本文件

- Windows 路径用原始字符串（Python 的 `r"..."`）写在 `.py` 文件里，不放进 heredoc 或 `-c` 参数。
- 多行中文、公式、Markdown 一律用编辑工具或脚本文件写入。
- 必须在命令行传参时，外层用单引号，内部不出现反引号。

## 规则 3：落盘后回读关键字段

写入后回读文件名、路径、数字、公式等关键字段。发现被吞立即修复，不把残缺内容当作成功交付。

## 违规信号

- 输出里出现 `command not found`，且命令行含反引号
- 落盘文件中本该出现文件名、公式或数字的位置是空白
- 追加操作返回成功，但回读内容与预期不符
- 写入的路径里出现缺字或奇怪的控制字符
