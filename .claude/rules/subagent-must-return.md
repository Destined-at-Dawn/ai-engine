# Subagent 必须归队规则

> 优先级：高（与 subagent-strategy 配套：那条管“何时启动”，这条管“启动之后”）
> 创建：2026-08-19 ｜ 更新：2026-09-24 ｜ 公开版：v5.2.0
> 来源：主代理说“不等了”，自己重写了一遍，已启动的 subagent 烧掉的 token 和已落盘的产出全部作废；另一次长时间并行任务因额度中断，结果只存在会被清空的临时目录里。

---

## 核心规则

**已启动的 subagent 必须归队。** 不得以“来不及”“不等了”为由放弃已启动的并行工作，然后自己重写一遍。放弃等于 token 白烧加重写无增量。

## 规则 1：等待并取回

```
Step 1: subagent 启动即进入“待归队”状态
Step 2: 等待完成（前台同步或后台完成通知）
Step 3: 取回最终产出（返回文本 + 落盘文件）
Step 4: 验收产出之后才宣布该任务结果
```

## 规则 2：产出必须验收

- 每个 subagent 独占写入目录，归队时检查文件时间戳、内容和哈希
- 验收不通过时，基于其产出定向续跑，不绕过重写
- subagent 自述“已完成”不是证据，回到文件核实

## 规则 3：异常如实报告

超时或异常终止时，报告已产出的部分，基于实际产出续跑，不假装没启动过或已完成。

## 规则 4：放弃前算清沉没成本

想放弃已投入的工作时，列出已投入的 token、时间和落盘产出，评估替代方案能否带来新信息。证明不了增量，就继续等或基于现有产出迭代。

## 规则 5：交接在启动之前写

启动长时间任务或多个 subagent 之前，主代理先在任务所在工作区写好交接文件：本次运行标识、结果回收位置、下一步。

- 每批结果返回后立即复制到任务工作区，并更新交接文件里的路径
- 会话临时目录、工具输出缓存可能被清空，不能作为唯一副本
- 部分工具会拒绝 subagent 自己写报告文件，交接不能依赖 subagent 写文件，由主代理写

## 规则 6：subagent 的写入目录在归队前受保护

派发时把它的独占写入目录记进本会话的“活跃写入目录”清单；本会话任何批量删除、移动、清理空目录的操作，先排除清单里的路径；归队验收后再移出清单。

“当前为空”不等于“不会被写”。刚创建、已交给一个仍在读取阶段的进程的目录，就是空的。任何“按当前状态批量处理”的脚本，动手前先问：这个状态是不是自己几分钟前刚制造的，还有别的进程依赖它吗？

## 违规信号

- 批量清理前没有排除活跃 subagent 的写入目录
- 说“不等了”并开始替代执行，subagent 产出未取回
- 声称“subagent 没产出”，但没检查它的写入目录
- 长时间任务的结果只存在临时目录，工作区里没有副本
