# 多智能体协作靠机制规则

> 优先级：高（与 version-baseline-check、subagent-must-return 同级）
> 创建：2026-09-20 ｜ 公开版：v5.2.0
> 来源：多个 AI 工具（Claude Code、Codex 及其他）在同一工作区并行改同一份稿件：两个会话各自走完同一流程，产出同一个修订号；同一天并行编辑规则文件导致多次修改静默丢失；前台的协调文件被另一个工具当作“无关文件”归档，五个修订号失去登记。
> 参考实现：`tools/agent-coord/coord.py`

---

## 核心规则

**多个智能体共用一个工作区时，协作靠可执行的机制，不靠约定和记忆。** 谁在改、现在是哪一版、下一个版本号是多少，都由磁盘上的租约、只追加登记和分配器回答。

## 规则 1：开工看状态，动手先认领，收尾跑体检

```bash
python coord.py status                              # 开工第一条命令
python coord.py claim --agent <名字> --task "..."    # 修改共享交付物之前
python coord.py next-rev --agent <名字>              # 需要新修订号时
python coord.py log --agent <名字> --action "..." --artifact <新文件> --baseline r12
python coord.py release --agent <名字>
python coord.py doctor                              # 收尾最后一条命令
```

`claim` 返回非零表示另一个智能体正持有租约。这时停手，不要“我先做我自己那份”。两个会话碰巧产出字节一致的文件是运气，不是机制。

## 规则 2：状态只信磁盘与登记

- 当前基线以状态文件和磁盘实况为准；两者冲突时以磁盘为准，跑 `doctor`。
- 压缩过的上下文、其他会话转述的版本号、几小时前读到的文件名，都不是证据。
- 修订号由分配器给出（扫描前台和归档取最大值加一，带锁），禁止自己数。

## 规则 3：登记只追加

协作登记用只追加的 JSONL 文件。多个会话同时追加不会互相覆盖；覆盖式写入的状态文件只放“当前是哪一版”这种可从登记重建的信息。

## 规则 4：跨工具规则写进每个工具都读的入口

不同工具读取的入口文件不同：Claude Code 读 `CLAUDE.md` 并自动加载 `.claude/rules/`；Codex 等工具读 `AGENTS.md`，不自动加载 `.claude/rules/`。

- 需要所有工具遵守的规则，写进 `AGENTS.md` 正文或协作目录，再让 `CLAUDE.md` 引用它。
- 写在只有一个工具读取的位置，等于只约束了这一个工具。
- 若用硬链接让两个入口共享一份文件，普通编辑器“写临时文件再替换”的保存方式会断开硬链接，之后两个工具各按一套规则工作且不报错。写完要复核硬链接数。

## 规则 5：协作目录不可清理

协作目录（租约、登记、状态、目录地图）禁止归档、移动或当作“交付无关文件”清理。在目录地图里登记它，让体检能发现它被移走。

## 规则 6：过程产物有固定落点

过程脚本、过程证据、被取代的交付物各有固定目录；根目录只出现目录地图登记过的项，`doctor` 逐项核对。
